# Audio/video workspaces

AppHeader, AppUi, AppNavigation and AppSections provide shared visual components. AudioActivity owns AudioController/AudioState/AudioDraftStore/AudioSelection; video selection, settings, retry state and saved session remain independent. Audio drafts persist URIs, names, bitrate, destination and card expansion in their own preferences. Read grants may require reselection after process death. Filename reading uses a separate lightweight executor and generation guards, with no media conversion on the UI thread.

## v0.62 · preliminary native conversion

Independent Audio foreground service and state; shared process-wide lease prevents overlap with Video. The lease remains owned until native return, decoder release, output publication and temporary cleanup. Activity polling runs only while visible; switching workspace does not stop a conversion. No audio restart/recovery is promised in this preliminary release.

Pinned, checksum-verified libraries: libopus 1.6.1, libopusenc 0.3, libFLAC 1.5.0. `AudioConverter` owns one file and its temporary resources; `AudioConversionService` owns only the queue/lifetime/progress. `AudioVerifier`, `AudioOutput`, `AudioReport`, `AudioActions`, `AudioLog` and `AudioCodec` have separate responsibilities. Separate `libaudioopus.so`; no MediaCodec encoder. Native FLAC decoding → interleaved float block → libopusenc resampling/Ogg packaging. Mono/stereo, native FLAC, 8–192 kHz, 4–32 bit; explicit rejection outside this scope. PCM FLAC MD5 checking enabled. No normalization. VBR unconstrained, application audio, complexity 10, chosen 64–256 kbit/s; all rate-control parameters read back and logged. Bitrate readback is checked after drain: multistream Opus distributes its target to child encoders only when encoding packets, so an early GET_BITRATE would still report their initialization value.

Each temporary Opus is independently extracted/fully decoded on Android and checked for channel count and PCM duration (80 ms tolerance for decoder trimming). Publication creates a fresh SAF document, adds a numbered name for conflicts, verifies copied length and removes partial documents on errors/cancel. Source documents are read-only. Report provides per-result open/error/copy actions and input/output sizes. Log is separate from Video, UTF-8 TXT, bounded to 2 MiB with an explicit cap marker, progress every 5 seconds, no sample/packet flood.

**Deliberate preliminary omissions:** tag/cover/LRC preservation and durable audio queue recovery. Warning shown in compression card and start confirmation. A successful result validates media conversion and decode, not metadata preservation or perceptual transparency. Playback on Samsung Music remains a device test.

CI: actual bundled native engine encodes 44.1 kHz 24-bit stereo, 48 kHz mono and 96 kHz stereo; FFmpeg independently decodes and asserts exact 1.1-second PCM length. Tests cover effective VBR parameters, cancellation, truncated FLAC and unsupported multichannel. Android build/lint and Java tests cover shared lease, bounded log, names/report and existing independent workspace behavior.


## v0.63 · metadata and explicit lyrics sidecars

The device v0.62 log and submitted 5,064,877-byte Opus passed independent full FFmpeg decoding. Source and output are not both available, so no perceptual quality comparison is claimed.

AudioMetadata (separate C++ module) collects every legal FLAC Vorbis comment without key allowlists, preserving raw UTF-8 bytes, repeated values and order. FLAC PICTURE blocks are serialized with their original image bytes, picture type, MIME, description, dimensions, depth and palette count, then stored as standard base64 METADATA_BLOCK_PICTURE comments. The completed OpusTags packet is read across Ogg pages and compared exactly with the expected list. Vendor identifies the new encoder; FLAC STREAMINFO, PADDING and SEEKTABLE are container/codec structures and not copied. CUESHEET, APPLICATION and unknown blocks cause an explicit error rather than silent data loss. Limits: 32 MiB combined comment storage, 100,000 entries, 16 MiB image payload; invalid tags/NUL or limits fail clearly.

External LRC files require a dedicated multi-select SAF picker. Drafts persist their own URIs/names. Matching uses the exact filename stem (case-insensitive), preferring a matching source parent when distinguishable; ambiguous matches fail. No unauthorized sibling search is attempted. Unselected/unmatched sidecars are explicitly reported in UI and per-file log. A matched sidecar is read up to 2 MiB without text decoding, and saved under the actual output audio stem, preserving BOM, encoding, newlines and timing. Audio and LRC names are reserved together to avoid existing documents. LRC readback is byte-equal, with SHA-256 in the log. Failure/cancellation before publication completes removes both new documents; existing documents are never deleted. A provider that changes the LRC filename is rejected.

Tests: independent Python FLAC/Ogg readers compare custom and repeated tags, Unicode, embedded lyrics, 70 kB multi-page comments, and two picture blocks exactly. Native fixtures cover 44.1/48/96 kHz and reject malformed tags/private APPLICATION blocks. Android provider tests exercise pair publication, failure rollback, corrupt readback, naming conflicts, sidecar matching and independent persistence.
